# Set up autohours conversationally

Install this skill by copying this entire `autohours-setup` folder into `~/.claude/skills/`. On Windows, use the `.claude/skills` folder inside the user's home directory. Codex and other agents can follow the repository's AGENTS.md instead.

Prefer the desktop download or `autohours gui` for a person who has never used a terminal. The app opens with no arguments, keeps titles local, and offers Back, Next and Cancel. Otherwise use `autohours setup` in the user's own interactive terminal. Use `autohours setup --add-project` to add a project to an existing config. The wizard asks one question at a time, supports back and quit, creates escaped rules from numbered activity choices, and asks separately before external writes and scheduling. Do not enter or retrieve the user's API key through agent tools; let them use the hidden local prompt.

If running an interactive wizard is impractical, follow its questions below and edit the config on the user's behalf. A non-technical user should never need to edit a file or write a regex. Use the README one-line installers for a new installation.

Ask for their timezone, destination and intended projects in plain English. Preserve existing settings. Do not treat setup as permission to write timesheets or enable a schedule.

1. Check Python 3.11+ and install this repository with `python -m pip install .` or `pipx install .`. On Windows, if `zoneinfo` has no IANA data, install `tzdata` into the same environment, or use `pipx inject autohours tzdata`.
2. Check ActivityWatch is running locally at `http://localhost:5600` and that window and AFK watchers are recording. If several hosts are present, ask which computer to use. Do not combine hosts. URL matching requires the browser extension, host metadata and a foreground title match; offer it only when useful.
3. Use `autohours setup` if no config exists. For agent-assisted manual setup, use `autohours init` and edit the timezone on their behalf before interpreting dates. Start with CSV while credentials or project decisions are pending. For Clockify, have the user enter the key at the wizard's hidden prompt from Profile settings, API, Generate, or set `CLOCKIFY_API_KEY` themselves. The wizard saves a Windows user environment variable or a private mode-600 credentials file under the user config directory on macOS/Linux. Environment variables take priority. Explain how to remove the saved key. Never ask them to paste the key into chat and never store it in TOML, scripts or source control.
4. Explain that unmatched output contains private local window titles. With their agreement to inspect this data, run `autohours unmatched yesterday` and the same command for two or three relevant explicit dates. Do not upload raw output or copy it into shared docs. If they prefer not to expose titles to an agent, have them summarize the projects themselves.
5. Propose projects and regexes based on their observed work, rather than generic guesses. Ask about ambiguous titles. Explain that any title, app or URL rule can match, and the first matching project wins. Put specific projects above general ones. Use single-quoted TOML regex strings. Keep descriptions fixed and safe for the destination. Confirm billable status rather than assuming it.
6. For each new project, ask about the agreement one question at a time. Start with billing type (`hourly`, `flat`, `retainer` or `none`), then rate and currency, break allowance, calls when away, rounding, and monthly cap. Never fill in a rate or currency the user has not given. Hourly without a rate is allowed and reports "rate not set". Billing type sets billable status; `none` is non-billable. Explain that flat and retainer track time without an hourly amount calculation.
7. Write the confirmed settings under `[projects.agreement]`. Use `[policy]` only for defaults the user wants across projects. Explain that merge gaps group nearby slices but do not bill excluded gaps. Rounding applies to billed duration and cannot overlap the next block. Run `autohours rules test` on representative titles and `autohours doctor`. Fix missing watchers, wrong project names and environment problems using its messages.
8. For Clockify, run `autohours rates` and show the exact differences. Only run `autohours rates --apply` after the user confirms the project, billable flag, hourly rate and currency. A currency mismatch refuses the project update. Inspect readback and report mismatches. No rate is invented or changed for flat and retainer agreements.
9. Run `autohours review` over the selected days before any `sync --write`, then `autohours sync` for the same dates without `--write`. Show worked and billed totals, away gaps excluded, counted breaks, calls, accepted time, rounding, unmatched time, discarded short blocks and existing-entry skips. Review allocates local activity from the month start when a cap exists; sync reserves already logged destination time, including manual entries, so its cap result can differ. Explain any held-back time. Adjust rules with the user until the proposed entries are useful.
10. Only run `autohours sync ... --write` after the user explicitly approves the dates and destination. Existing entries win on overlap; never delete or modify manual entries to force a sync. After a partial failure, review and dry sync again before retrying. Do not run concurrent writers.
11. Offer scheduling only after a successful manual run and separate approval to automate writes. Prefer the wizard's schedule preview and explicit confirmation. `autohours schedule --remove` undoes its daily job. Follow `docs/scheduling.md` for manual alternatives, using absolute paths and private credential storage. Explain that daily `yesterday` runs do not backfill several missed days.

## Translate ordinary requests

"Breaks under five minutes count" becomes `count_breaks_up_to_minutes = 5` in that project's agreement, or policy if the user means all projects. Explain that this setting includes a break of exactly five minutes. It applies only to observed away gaps inside a merged block. Missing AFK coverage remains excluded.

"Calls count even when I look away" becomes `count_calls_when_away = true`. Check the actual foreground call app or title against the configurable `call_apps` and `call_titles` regex lists. Calls still need a matching project and AFK evidence.

"That gap from 2 to 2:30 was a call for Acme, accept it" becomes `autohours accept DATE 14:00 14:30 --project Acme`, after resolving the date and exact configured project. This explicitly confirms work; it does not change the project's general call policy. `autohours accepted [DATE]` lists IDs and `autohours accept --remove ID` removes a correction. Removing one does not delete a destination entry. Accepted time replaces overlapping observed evidence and still respects destination overlap checks and monthly caps. Notes remain local unless the user deliberately puts their text in the configured description.

Use `autohours review DATE --html PATH` for a self-contained report. Keep reports outside the repository. Titles are omitted by default; only add `--titles` when the user explicitly wants private window titles in the report. Project names, rates and totals can also be sensitive. Never share a report without reviewing its audience and contents. Keep accepted files and scheduler logs private too.

Stop for missing user choices that affect billing or external writes. Routine read-only checks and reversible config edits can proceed within the user's setup request. Never invent activity when the laptop slept, the phone was used, or AFK coverage is missing.

## Desktop workflow

Use the masked local key entry, Check key, and workspace dropdown. Select a project and tick actual activity items; the coverage percentage counts unique active time rather than adding overlapping categories. Confirm descriptions and all agreement fields. Spreadsheet skips the Clockify steps. Back does not undo saved settings or completed writes.

Save settings, check rate differences, and review yesterday. Apply to Clockify shows the exact changes for separate approval and reads them back. Write this day shows a dry sync before confirmation. Enable nightly writes only after separate approval of the exact schedule. Home can review another date, open a private HTML report, edit projects, or remove the nightly job. Private dated logs live under the user config folder and expire after 30 days. Move packaged apps to their final location before scheduling. Never put logs, reports or activity screenshots in the repository.
